# コーディング規約

この文書は Hestia リポジトリのソースコードに適用する書式を定める。設計と作業手順は [AGENTS.md](../AGENTS.md)、改行・インデント・文字コードはルートの [.editorconfig](../.editorconfig) を参照する。

ヘッダーと実装の記述例は [CodingExamples](CodingExamples.md) を参照する。

## 命名

- 名前空間、型、列挙型と値、関数、ファイル名は `UpperCamel` とする。
- ローカル変数と引数は `lowerCamel`、通常メンバは `m_lowerCamel`、static メンバは `s_lowerCamel` とする。
- マクロと名前付き定数は `UPPER_SNAKE_CASE` とする。一時的な `const`／`constexpr` ローカルは `lowerCamel` とする。
- API テーブルの公開関数ポインタは関数と同じ `UpperCamel` とする。
- 命名規則は新規コードと変更箇所に適用し、無関係な既存コードは一括改名しない。

## インクルードガード

- `#ifndef`／`#define`／`#endif` 形式を使う。
- ガード名はファイル名を大文字にし、単語の区切りに `_` を使い、先頭と末尾にも `_` を付ける。例: `Engine.h` は `_ENGINE_H_`、`GraphicsSystem.h` は `_GRAPHICS_SYSTEM_H_`。
- PCH はプロジェクト名を先頭にした `_<PROJECT>_PCH_` を使う。

## コメント

- コメントは日本語を基本とする。ただし、クラス名・関数名などコード上の識別子はそのまま使う。`LogStorage` を「保持先」と言い換えるなど、対応する型や処理が分かりにくくなる変換はしない。
- 句点はなるべく使わず、「設定の妥当性を確認」「残件を処理」のような短い表現で終える。
- Doxygen を含むコメントは、原則として行コメントで記述する。
- Doxygen コメントには `///` を使い、公開 API の概要、引数、戻り値、前提条件など利用側が必要とする契約を記述する。
- 戻り値は「成功: true / 失敗: false」のように、条件と結果を直接対応させる。
- 通常のコメントには `//` を使う。処理単位の先頭に見出し的なコメントを置き、何をしているかを短く示す。複雑な処理ほど段階ごとの見出しを増やし、流れを追いやすくする。
- 見出しだけでは伝わらない前提・理由・例外条件は必要な箇所で補足する。コードを一行ずつ言い換える説明や装飾的なコメントは避ける。

## 処理の構成

- 単文の `if` は波括弧を省略し、早期 return で正常経路のインデントを浅くする。
- 関数間と意味の異なる処理単位を空行で区切る。関連する処理はまとめ、見出しコメントと合わせて構造を読み取りやすくする。
- クラスの責務に属する内部処理は、そのクラスの private メンバ関数に置く。小さな委譲関数は素直に書く。
- 参照用の構造体・列挙体は、関連するものを一つのファイルにまとめる。値型ごとの細かなファイル分割は避ける。

## ファイルヘッダー

- `.h` と `.cpp` の各ファイル先頭に、次の形式でブロックコメントを記述する。
- `Date` はそのファイルの作成日を `YYYY/MM/DD` で記録し、`Author` は `Yokoyama Haruki` とする。
- `Desc` はファイルの役割を簡潔に記述する。

```cpp
/*=============================================================================

 File   : Engine.h
 Desc   : Engineクラス - 各Systemと更新処理を管理する。

------------------------------------------------------------------------------

 Date   : 2026/10/07
 Author : Yokoyama Haruki

===============================================================================*/
```

## include パス

- 同一プロジェクト内の Header は、そのプロジェクトの include path を基準にファイル名で指定する。
- 別プロジェクトの Header はリポジトリルートからのパスで指定し、依存先プロジェクトが分かるようにする。例: `#include "Engine/Include/EngineAPI.h"`。
