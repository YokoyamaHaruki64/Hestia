# 実装前の未確定事項と資料間の差分

以下は決定済み事項の再議論ではなく、実装で具体的な型や順序が必要になる論点である。「資料に明記された内容」は根拠、「実装リポジトリ向けの提案」は進め方であり、採用決定ではない。

| 論点 | 資料に明記された内容・差分 | 判断に必要な情報／実装リポジトリ向けの提案 |
| --- | --- | --- |
| Engine の最小境界と失敗 | [Engine](../Reference/HestiaDesign/DevelopNotes/Class/Engine.md) は `GetEngineAPI`、Handle 付き `Create`／`Destroy`／更新を示す一方、`Create` 失敗通知と共有 Header／`ENGINE_API` 配置は未定。[OpenQuestions U02](../Reference/HestiaDesign/DevelopNotes/OpenQuestions.md) は独立した API テーブル `Initialize`／`Finalize` を退ける。 | 最初の実装では API テーブルの配置、`Create` 失敗の返し方、部分初期化時の解放順を決める。Window と Engine.dll の最小ロード／破棄を確認する。 |
| ApplicationAPI と既存コード | [Application](../Reference/HestiaDesign/DevelopNotes/Class/Application.md) は `Hestia::ApplicationAPI` と `GetWindowHandle` を定めるが、現行 [Application.h](../Application/Include/Application.h) はグローバル `ApplicationAPI` で HWND 取得口がない。Engine ロード部分はコメント化され、[Engine/dllmain.cpp](../Engine/dllmain.cpp) は入口だけ。 | 共有 Header の責務を決め、現行コードとの差分を小さく実装する単位に分ける。今回はコードを合わせない。 |
| Window Message と終了 | [Application](../Reference/HestiaDesign/DevelopNotes/Class/Application.md) は毎フレーム先頭の ProcessMessages、Engine／Editor への void 通知、最後の DefWindowProc、Window の破棄を示す。現行 [Application.cpp](../Application/Source/Application.cpp) は Run 先頭から `ProcessMessages` を呼ばず、Engine 通知も未実装。[Window.cpp](../Application/Source/Window.cpp) の Finalize は `UnregisterClass` と `CoUninitialize` を行う。 | 実装時にメッセージ配送と Window 破棄の順を確定し、閉じる操作とタイマー待機中の応答を実機で確認する。 |
| System と Boundary API | [SubsystemApiFacadeDesign](../Reference/HestiaDesign/DevelopNotes/SubsystemApiFacadeDesign.md) は Engine 値所有と `Initialize(XxxSystem*)` を決定。個別の [AssetSystem](../Reference/HestiaDesign/DevelopNotes/Class/AssetSystem.md) と [Subsystems](../Reference/HestiaDesign/DevelopNotes/Class/Subsystems.md) は機能 API や一部 lifecycle を追加草案として留保する。 | 各 System を実装する直前に Game 側の一つの用途を決め、必要な公開操作、共有型、更新順、`s_instance` の登録・解除時点を確定する。一律の System 初期化規約を先に設けない。 |
| Asset Facade の経路 | [AssetManagement](../Reference/HestiaDesign/Asset/AssetManagement.md) 等は `Assets::Load<T>`、`GameAPI.lib` と `Engine::AssetDB` を想定する。[OpenQuestions U07](../Reference/HestiaDesign/DevelopNotes/OpenQuestions.md) は元の Asset 例の Load／Handle 宣言を取り下げ、[AssetSystem](../Reference/HestiaDesign/DevelopNotes/Class/AssetSystem.md) は公開操作を未確定とする。 | Asset の最初の利用ケース、所有する Cache、`AssetHandle<T>` の無効化条件、Game 向け API の配置を確認してから統合する。GameAPI.lib を現在の必須構成としない。 |
| CPU Asset と GPU 資源 | [AssetType](../Reference/HestiaDesign/Asset/AssetType.md) は CPU Asset を Cache、DX12 Resource／Descriptor を Graphics 側に分ける草案。[Material](../Reference/HestiaDesign/Asset/Material.md) は型付き Material 値と Reflection の GPU Layout を分ける。アップロード要求 API、Ready 時点、借用参照の寿命、Frame への固定方法は未決。 | Mesh／Texture の一つの読み込みから描画までを対象に所有者・同期点・失敗通知を決める。Game 公開 API に DX12 実体を漏らさない方針を候補とする。 |
| 初期描画と後段案 | [RenderingArchitecture](../Reference/HestiaDesign/Graphics/RenderingArchitecture.md) 冒頭は 2026-10-04 更新として Main Thread の直接経路を優先し、後半の Render Thread／FramePacket を比較案とする。[MultiThreadRendering](../Reference/HestiaDesign/DirectX/MultiThreadRendering.md) は Render Thread を前提に Build→Sort→Record を描く。[RenderingPipeLine](../Reference/HestiaDesign/Graphics/RenderingPipeLine.md) と [RenderGraph](../Reference/HestiaDesign/Graphics/RenderGraph.md) は Graph 利用を説明するが、DirectX 資料は初期 Pass／Barrier の明示管理を採る。 | 最小描画の要求型、初期 Pass／Barrier、Main Thread 上の呼出し順をまず定義する。描画スレッド・Graph・Worker 分割の採用時期は実測と必要機能で判断する。未収録の `SimpleArchitecture` 等を確認するまでは、その記述を決定根拠にしない。 |
| ECS／World／GameRuntime | [Plan2](../Reference/HestiaDesign/ECS/ECSArchitecture_Plan2.md) は C++ Sparse Script を現在の方針、初期は通常の `.h/.cpp` と Game.dll、Generator は後段とする。[Plan1](../Reference/HestiaDesign/ECS/ECSArchitecture_Plan1.md) は C# Script 案を含む。[GameRuntime](../Reference/HestiaDesign/DevelopNotes/Class/GameRuntime.md) はゲーム状態の所有型を仮置きとし、Engine の `WorldSystem` は宣言されていない。 | 最初に必要な Entity／Script 操作、NativeECS と GameRuntime の所有境界、登録解除の時点を、具体的な Game 用途から決める。Plan1 の C# や Plan2 の Generator を初期要件へ持ち込まない。 |
| Editor の配置 | [Class/Editor](../Reference/HestiaDesign/DevelopNotes/Class/Editor.md) と [OpenQuestions U08](../Reference/HestiaDesign/DevelopNotes/OpenQuestions.md) は Application の条件付き値所有のみ確定し、DLL／exe 配置と情報経路を後回しにする。一方、[Plan2](../Reference/HestiaDesign/ECS/ECSArchitecture_Plan2.md) は Editor コードを Editor プロファイル exe に含めると記す。描画資料は exe 内 ImGui との接続案を持つ。[RenderingArchitecture](../Reference/HestiaDesign/Graphics/RenderingArchitecture.md) | Runtime と Game の最小実装後、Editor が編集する状態と GPU 表示の接続を列挙し、配置・依存・初期化順を決める。現時点でいずれかの配置を採用済みと宣言しない。 |
| Game → Application | [OpenQuestions U03](../Reference/HestiaDesign/DevelopNotes/OpenQuestions.md) は別 API を GameRuntime へ渡す方向だけ決め、型・操作・引数を未確定とする。 | Game が直接必要とする FPS 設定や終了要求等の用途を列挙し、既存 ApplicationAPI の利用か Game 用の限定 API かを選ぶ。 |
| DLL 内 C++ 型の契約 | [SubsystemApiFacadeDesign](../Reference/HestiaDesign/DevelopNotes/SubsystemApiFacadeDesign.md) は Handle／ID／POD／明示 View を勧める。[Plan2](../Reference/HestiaDesign/ECS/ECSArchitecture_Plan2.md) は同一ビルドの内部 C++ 境界で STL／template 等を一律禁止しない。[Material](../Reference/HestiaDesign/Asset/Material.md) も Game 側から直接操作する API／ABI を未確定とする。 | 共有 Header と各 API の実際の引数・寿命・コンパイラ／Runtime 設定をレビューして決める。外部安定 Plugin ABI を先に要求しない。 |

**資料に明記された範囲の不足**：このコピーには独立した `Runtime/`／`Editor/` 資料、Input・Audio・Physics の個別機能資料、参照先の `SimpleArchitecture` 等がない。[DesignSources](./DesignSources.md) のコピー時点と収録範囲を超えた判断は保留する。
