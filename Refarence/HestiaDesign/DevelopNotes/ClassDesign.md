# Class Design
## 目的
この資料では、クラスの**概念設計・ホワイトボード設計**を行う。

この段階で決めるのは主に次の内容。

- クラスの責務
- 何を所有し、何を参照するか
- 主要なメンバ構成
- 外部へ公開する主要 API
- 他クラスとの大まかな関係
- 必要なら処理の流れ

「安全に完成させるための設計」ではなく、**今考えるために必要な最小限の設計**を優先する。


## 基本方針
設計順は原則として次の順番にする。

1. 責務を決める
2. 所有するもの・参照するものを決める
3. 主要なメンバを置く
4. Public API を決める
5. 各 API がどのメンバを操作するか確認する
6. 責務が明確に独立している場合だけ内部クラスや Subsystem に分割する
7. 必要になった段階で保証・エラー処理・安全性を追加する

最初から完成形を目指さない。


## この段階では原則として入れないもの
明確な要求がない限り、以下を設計へ追加しない。

- Thread Safety
- 例外安全性
- 不正な呼び出し順への完全な対策
- 厳密なライフタイム保証
- Validation 層
- Result / Expected 型
- Factory
- 抽象 Interface
- 過剰な RAII Wrapper
- 世代管理や複雑な Handle 管理
- 将来の拡張だけを理由にした抽象化
- 「念のため」の Manager / Service / Adapter
- エラー状態を完全に表現するためだけの状態機械

これらが将来的に必要そうでも、現在の責務や API を考えるために不要なら保留する。


## 分割ルール
クラスを分割するのは、責務が明確に独立している場合だけ。

「将来大きくなりそう」
「テストしやすそう」
「安全性を保証しやすそう」

だけを理由に分割しない。

まず単純な 1 クラスとして形を出し、そこから責務が自然に分かれる場合だけ分割する。


## 不明点の扱い
不明点を新しい抽象化で解決しない。

判断材料が不足している場合は、

- `TBD`
- `要検討`
- 仮置き

として残してよい。

未決定事項を無理に確定させるより、現在確定している構造を明確にすることを優先する。

## コード例
```cpp
class Renderer
{
public:
    bool Initialize(...);
    void Shutdown();

    void BeginFrame();
    void Submit(const RenderItem& item);
    void Render();
    void Present();

private:
    Device* m_device = nullptr;

    RenderQueue m_renderQueue;
    FrameContext m_frames[FrameCount];

    uint32_t m_frameIndex = 0;
};
```

この段階では、

- `Present()` が二重に呼ばれた場合
- `Submit()` 中に別スレッドからアクセスされた場合
- Device Lost
- Shutdown 中のアクセス
- すべての API の戻り値設計

などを先回りして解決しない。

まず `Renderer` が何を持ち、外から何をさせるクラスなのかを決める。


# AI / Codex 向け指示
以下をクラス設計時の基本指示として使用する。

> クラスの概念設計・ホワイトボード設計を行ってください。
>
> 目的は、責務・所有関係・主要メンバ・主要な Public API を決めることです。
>
> 現段階では完成形や堅牢性を求めません。
> 「実運用上必要な最低限」ではなく、「現在の構造を考えるために必要な最低限」を提示してください。
>
> 明確に要求されていない限り、Thread Safety、例外安全性、不正呼び出し対策、厳密なライフタイム保証、Validation、Result 型、Factory、抽象 Interface、過剰な RAII Wrapper、将来拡張のためだけの抽象化を追加しないでください。
>
> 不明点は新しい層や仕組みを追加して解決せず、TBD または要検討として残してください。
>
> まず単純な 1 クラスとして考え、責務が明確に独立する場合だけ分割してください。
>
> 出力では、各クラスについて最低限以下を示してください。
>
> - 責務
> - 所有するもの / 参照するもの
> - 主要メンバ
> - Public API
> - 他クラスとの関係
> - 未決定事項
>
> 実装コードは不要です。必要なら API とメンバが分かる C++ のクラス宣言だけ示してください。
